# 双雷达一键二维建图与栅格导出

入口：`src/navigation/navi2_bringup/launch/dual_lidar_mapping.launch.py`。启动双雷达驱动、Point-LIO、点云转扫描、slam_toolbox、栅格缓存导出器及 RViz。不启动 GICP、导航控制、决策或通信节点；PTP 仍使用已验证的独立同步服务。

## 当前机器直接启动（不需要构建）

先结束已有的驱动/Point-LIO，避免重复占用雷达端口。保持正常 PTP 服务运行。

```bash
cd /home/robomaster/2027-sentry-navi
source /opt/ros/humble/setup.bash
source install/setup.bash
# 本机系统尚未安装转换包，先仅加载已有的这个官方单包。
# 不要 source 整个 fwh 工作空间，避免切换驱动与 Point-LIO。
source /home/robomaster/fwh/install/pointcloud_to_laserscan/share/pointcloud_to_laserscan/local_setup.bash

ros2 launch /home/robomaster/2027-sentry-navi/src/navigation/navi2_bringup/launch/dual_lidar_mapping.launch.py
```

以后也可由用户自行安装官方二进制依赖，替代上面加载 fwh 单包的一行：

```bash
sudo apt install ros-humble-pointcloud-to-laserscan
```

本次尝试安装时 sudo 要求本机密码，未安装或改变系统软件。已核对只加载上述单包后，`point_lio` 与 `livox_ros_driver2` 仍指向本仓库安装目录。入口用绝对源码路径，因此 navi2 尚未构建也可以运行。未来构建并安装 navi2 后，也可使用 `ros2 launch navi2 dual_lidar_mapping.launch.py`。

默认输出到本机 `~/maps/mapping_年月日_时分秒/`。如需指定目录，在启动命令末尾加 `output_dir:=$HOME/maps/site_a`；这个目录内的 `map.pgm`、`map.yaml` 会随检查点更新，已有同名地图会被更新，请为新场地使用新目录。

## 采集与结束

先静止等待 IMU 初始化与 `/map` 出现，再低速巡视场地，经过墙角和共同结构，最后回到起点观察错层、重影。专用 RViz 固定系为 `map`，完整点云使用 Best Effort，地图使用 Transient Local。地图未产生前，RViz 暂时没有 `map` TF 属于初始化状态。

收到第一张有效栅格后立即保存一次，之后每 10 秒保存。结束时在 launch 终端按 **Ctrl+C**，导出器从自己缓存的最后一张 `/map` 保存 `map.pgm` 与 `map.yaml`，不依赖 slam_toolbox 在退出时仍提供服务，也不依赖 Point-LIO 的 PCD 析构保存。输出分辨率默认 0.05 m/cell。

没收到有效 `/map` 时会报告错误，不伪造空地图。SIGKILL、断电和磁盘写入失败不保证最后一次保存；已有周期检查点用于减少损失。PGM 上下行方向、YAML 的 origin/yaw、未知/空闲/占据单元已检查；未知使用灰度 128，使其按 YAML 的 0.25/0.65 阈值重新加载后仍为未知，规则参见 [Nav2 Humble map_io](https://github.com/ros-navigation/navigation2/blob/humble/nav2_map_server/src/map_io.cpp)。

这是 **slam_toolbox 的二维地图**，不是 Point-LIO 三维 PCD 的自动导出。若后续 GICP 需要 PCD，应另外生成并核对 PCD 与二维地图的坐标；不能默认带回环修正的二维地图与未经相同修正的三维 PCD 自动一致。

## 安装高度和角度

配置文件：`src/navigation/navi2_bringup/params/dual_lidar_mapping.yaml`。用户实测主雷达中心高 **0.42478 m**，绕自身 x 轴倾斜 **45°**。正负号尚未独立机械确认；静止 bag 的主 IMU/odom 初始 roll 约 -46.13°，因此当前投影配置使用 **-π/4 候选值**，不是重新标定或给 Point-LIO 强加角度。

已有配置的含义：

| 配置/变换 | 作用 | 不表示什么 |
|---|---|---|
| `merge_extrinsic_back_to_front` | 副雷达到主雷达 | 不表示主雷达离地高度 |
| Point-LIO `mapping.extrinsic_T/R` | 雷达到 IMU，`p_I=R_I_L p_L+T_I_L` | 不表示底盘或地面位置 |
| 现有 `camera_init -> body` | 估计的 IMU 位姿 | 初始 Z 通常不是物理离地高度 |
| 现有 `camera_init -> slambase` | 使用 IMU 的位置、仅保留 yaw | 不是地面投影原点 |
| 新增 `slambase -> mapping_ground` | 根据安装测量向下平移，供本次二维投影 | 不替代原有 `base_link`，不约束滤波器 Z 漂移 |

对绕自身 x 轴的安装，入口读取同一 Point-LIO 参数文件中的固定 `R_I_L/T_I_L`，计算：

```text
R_W_L = Rx(lidar_roll_rad)
R_W_I = R_W_L * R_I_L^T
h_IMU = lidar_height - (R_W_I * T_I_L).z
```

按当前 `T=[-0.011,-0.02329,0.04412] m`、`R=I` 和 -45° 得到 IMU 高度约 **0.37711 m**，所以新增地面参考向下平移约 0.37711 m。不能把 0.42478 m 直接填进 `extrinsic_T.z`。用户测的是雷达外壳中心，点云原点与外壳中心的细小偏移尚待核对；若安装还有其他俯仰角，本入口仅绕 x 的假设也需要补充测量。

投影截取范围默认相对 `mapping_ground` 为离地 0.10—1.20 m，起步值用于排除地面、截取主要障碍，应根据本车低障碍与车体高度要求调整。核验时检查实际地面在 `mapping_ground` 下是否接近 Z=0，改变高度不能用于掩盖明显的外参或姿态错误。

URDF 或静态 TF 可以描述机械固定安装关系，但不会自动测量高度或强制 Point-LIO 的地面高度不变。真实底盘坐标还需要 IMU/雷达相对底盘中心的 X/Y、轴向和安装关系；本次没有这些测量，所以没有覆盖原代码中 `(0,0.20,0)` 和单位姿态的 `base_link` 逻辑，也没有给同一 child frame 重复发布 TF。

## 检查范围

使用已录制的全程静止 bag，在独立 ROS 域禁用传感器启动，完成约 15 秒回放：收到 14 张栅格，导出 250×67、0.05 m/cell 的 PGM/YAML。另用合成栅格确认：第二次地图更新尚未周期保存时，SIGINT 会保存最后缓存；没有输入则退出报错且不生成假地图。

这验证建图链路和导出功能，不是完整场地、动态稳定性或安装几何的最终验收。测试只在临时子进程引入 fwh 的转换单包，未切换本仓库驱动、未构建、未改 PTP、未启动控制器。实际巡视后的地图质量仍需现场检查。
