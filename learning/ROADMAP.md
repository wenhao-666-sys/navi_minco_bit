## 一、目标、起点与学习方式

学习主线：**理解工程 → 独立部署 → 有依据地调参 → 读懂源码 → 验证框架优化**。每阶段有实际产物和验收标准，后续按课程编号续接。

已确认条件：

- 学习者能运行 ROS 项目，使用过 RViz；终端、C++、ROS 和数学知识结合实际问题补充。
- 实践平台是 Ubuntu 22.04、ROS 2 Humble、NUC、双 MID-360 和轮式底盘。
- 这份代码尚未在 NUC 上编译运行；本计划的静态源码核查不能替代构建和实机证据。
- 学习对象是独立的 navi_minco_bit 仓库，与 USV-navigation 分开。
- Foxglove 覆盖 NUC 本机、Windows 远程和离线数据分析。

| 阶段 | 完成后的能力 | 核对方式 |
|---|---|---|
| 初期：工程与部署 | 解释全部目录和文件类别，找到功能入口，独立配置和部署 | 从环境检查到启动闭环复现一次，解释输入、输出和失败原因 |
| 中期：参数与实验 | 找到参数、生效机制和调整依据，能用数据判断结果 | 完成定位、地图、规划、控制四类对照实验 |
| 末期：源码与优化 | 沿数据流阅读源码，对应算法与实现，完成一个里程计改进课题 | 交付调用链、修改方案、回归结果和优化报告 |

每单元可拆成多次教学。建议每次围绕一个小目标安排约 60—90 分钟讲解和操作；总进度按掌握情况推进。下表复选框仅在用户实际达到验收要求后勾选，教材写好不算通过。

## 二、初期：结构、部署与 Foxglove

### 项目全景

```text
双 MID-360 点云与 IMU
  → Livox 驱动、时间配对、双雷达融合
  → Point-LIO：连续局部里程计与配准点云
       ├→ GICP：先验地图对齐 → map 与局部参考系关系
       └→ ROGMap：占据、地形投影、距离场
                → 搜索与 MINCO 轨迹 → MPC 跟踪 → 通信与底盘

比赛行为树：上层任务与策略
Nav2：导航执行、插件、生命周期等工程组织
```

全文件索引覆盖每个已跟踪文件的模块、类别、用途和阅读入口。核心业务代码在后期沿调用链深入；第三方代码先了解用途与调用边界，再按课题阅读。按名称/位置归类的文件会明确标注说明粒度，不能把索引当作逐行代码审计。

| 模块组 | 包或目录 | 学习重点 |
|---|---|---|
| 工程入口 | 根脚本、scripts | 构建、启动、录制、监测、路径、环境 |
| 雷达接入 | livox_ros_driver2、dual_lidar_calibration | 网络、消息、融合、外参 |
| 里程计与定位 | point_lio、icp_relocalization | 局部估计、去畸变、地图对齐 |
| 环境感知 | rog_map、msg_convert、dbscan_cluster | 占据、地形、ESDF、过滤、聚类 |
| 规划与控制 | navi2、minco_planner、minco_controller | Nav2、搜索、优化、MPC |
| 决策与执行 | bt_manager、communication | 行为树、状态、协议、底盘 |
| 自定义接口 | ros_interfaces | 轨迹、比赛状态和行为消息 |
| 仿真 | sentry_simulation | 模型、桥接、运动学、真值 |
| 地图工具 | pcd2pgm、pcd2ele、pcd2esdf、pcd_trans | 离线转换编辑；pcd_trans 不是独立 ROS 包 |

目录名与包名分开学习：Point-LIO 对应 point_lio，navi2_bringup 对应 navi2。

### IP 对齐的具体关联

1. 查 NUC 实际网卡、地址、掩码和路由。
2. 查两台雷达实际 IP，明确哪台作为参考雷达与 IMU 来源。
3. 对齐驱动 JSON 的主机接收地址、接收端口和雷达地址。
4. 对齐融合配置中的前后雷达 IP。
5. 对齐从 IP 派生的 IMU 话题与 Point-LIO 订阅。
6. 核对 launch 对 YAML 的覆盖。
7. 用消息类型、频率、时间戳、有效点和连续输出验收。

仓库主机 `.47`、前雷达 `.135`、后雷达 `.122` 仅作为阅读样例。部署使用真实设备数据；ping 成功只是检查的一项。单雷达配置还使用不同 IP/接收端口，不与双雷达配置混用。

### Foxglove 安排

NUC 运行 ROS 与 foxglove_bridge；本机连接 `ws://localhost:8765`，Windows 连接 NUC 在客户端网络上可达的地址。先使用局域网和本地数据。[官方 ROS 2 接入说明](https://docs.foxglove.dev/docs/getting-started/frameworks/ros2?modality=live)

| 布局 | 观察内容 | 用途 |
|---|---|---|
| 传感器与定位 | IMU、里程计、配准点云、TF、原始字段、日志 | 输入、坐标、时间、漂移 |
| 地图与规划 | 先验、ROGMap、搜索、优化与预测路径 | 地图表达与规划合理性 |
| 控制与性能 | 指令/估计速度、姿态、误差、性能统计 | 抖动、延迟、超调、计算开销 |

项目适配：

- `/livox/lidar` 为 CustomMsg，先看原始字段；3D 优先使用现有标准点云输出。
- `/opt_path` 为自定义轨迹；三维路径使用 `/opt_path_vis` 等可视化输出。
- 3D 依赖时间戳与有效 TF，安排“有消息但看不见”的故障练习。[官方 3D 面板说明](https://docs.foxglove.dev/docs/visualization/panels/3d)
- 点击发布需核对消息、坐标和接收端，不能假设所有 RViz 交互都有相同作用。
- 新录制使用 MCAP，录制端加载自定义消息；Humble 旧式 db3 的自定义消息定义需额外处理。[官方录制说明](https://docs.foxglove.dev/docs/getting-started/frameworks/ros2?modality=live)
- 区分查看已录结果与重新运行算法；后者需要原始传感器输入及正确时钟/TF，且避免旧结果与新算法输出冲突。

完整操作与三套布局配方见 [Foxglove 手册](foxglove/README.md)。导入验证后的布局文件在 A04 实际连接数据后保存；当前不把配置配方称为已验证布局。

**初期阶段门槛：** 工程结构解释、部署复现、Foxglove 主数据观察和至少三类故障归因均有证据。

每次回答：**调什么 → 在哪里生效 → 预期改变什么 → 可能损失什么 → 用什么验证。**

| [ ] | B04 | GICP 初值、裁剪、体素、积累、质量、稳定性、回退 | 不同初值误差下成功率、耗时、误接受比较 |
| [ ] | B05 | ROGMap 分辨率/窗口/概率/衰减/投影/prior/ESDF，与 costmap 对照 | 固定障碍实验解释出现、消失、通道及高度分类 |
| [ ] | B06 | 模式、搜索、前视、速度/加速度、安全距离、权重、重规划 | 到达率/长度/最小距离/耗时/失败比较 |
| [ ] | B07 | MPC dt、控制频率、时域、Q/R、延迟、约束 | 直线/转弯/S弯/停车的误差、超调、停止距离 |
| [ ] | B08 | 定位/地图/规划/控制/执行故障归因与联合调优 | 失败数据定位问题层，提出单参数族实验并给结论 |

实验表统一使用 [参数实验模板](templates/EXPERIMENT_RECORD.md)，包括版本、参数版本、路线、初值、问题、旧值/新值/单位、生效方式、预期、结果、失败样本和保留/回退理由。

固定场景：静止、直行、原地旋转、转弯/S弯、障碍移入移出、窄通道、目标取消/输入中断。先仿真或回放，再做实机验证；实机门槛在 B02 根据底盘能力和基线确定，随后比较前固定。

必须掌握：

- 参数服务接受修改不代表初始化缓存或算法成员已改变。
- 控制循环频率与 MPC 模型 dt 不同。
- 绝对 Z 扫描范围、安装高度和障碍高度差不同。
- 三维衰减与二维保持属于不同阶段。
- 外参、坐标和单位是接入事实，先校准后调优。
- 记录 Foxglove/录包/额外订阅开关，测量观察工具的负载。

**中期阶段门槛：** 定位、地图、规划、控制四类对照报告齐全，并解释一次失败调参的回退理由。

### 里程计优化毕业课题

| 完成 | 编号 | 工作 | 验收 |
|---|---|---|---|
| [ ] | O01 | 固定数据、参数、环境，记录阶段耗时/点数/队列/CPU/内存/输出/轨迹 | 相同输入有可重复比较的基线 |
| [ ] | O02 | 按 profile 在 batch、iVox、稠密点云、复制、调度中选一项 | 瓶颈证据、假设、条件及事前指标 |
| [ ] | O03 | 有边界地实现、补回归、比较新旧实现 | 解释机制，约定正确性回归通过 |
| [ ] | O04 | 综合回放/仿真/实机结果，评估收益与代价 | 可复现报告、退化案例、回退方法 |

评价维度：

- 计算：p50/p95/p99 耗时、处理间隔、积压、CPU/RSS。
- 估计：有真值用轨迹/相对运动误差；无真值用静止漂移、返回起点、重影等代理指标，并明确局限。
- 接口：话题、类型、frame、时间戳、单位、QoS、下游消费需求。
- 系统：地图、规划和控制是否因改动退化。

时间指标需要可比时基；历史 bag/仿真时间与当前 Unix 时间直接相减不能代表计算耗时。使用 [优化报告模板](templates/OPTIMIZATION_REPORT.md) 记录。

**末期阶段门槛：** 证明问题、解释方案、验证结果；允许实验结论是无收益或退化，不能预先承诺性能提升。是否替换框架依据课题结果另行决定。

## 五、长期核对与教学安排

维护路线图、全文件索引和 [PROGRESS](PROGRESS.md)。布局、参数实验、调用链、测试报告按课程编号关联；原始录包独立存放并记录路径/校验信息。

状态：`未开始 → 学习中 → 已实操 → 已验收 → 待复习`。纯阅读课的“已实操”指完成查找、追踪或解释练习，不要求启动机器人。验收必须有用户输出或实测证据。

每课流程：目标 → 输入输出 → 生效文件 → 预测 → 操作 → 差异分析 → 复述/独立操作 → 更新记录。每阶段复盘；阻塞先归类环境、配置、输入、算法、执行，再补对应课程。

### 第一课安排

从 [A01](lessons/A01_PROJECT_OVERVIEW.md) 开始：根目录、六组源码目录、17 包；各导航模块职责；雷达输入和目标输入两条链；实际启动脚本的启用/关闭项；完成模块图。
